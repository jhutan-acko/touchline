# Touchline

A multi-agent football match-intelligence engine on Azure, built for the Microsoft *Inside the Game* hackathon. All data is synthetic: clubs, players and matches are fictional and generated by our own simulator.

## Quick start

```bash
corepack enable
pnpm install
pnpm league                                   # regenerate data/league/league.json (deterministic)
pnpm test                                     # all TypeScript tests
pnpm sim --seed 1 --home ironmoor --away saltmarsh   # writes out/m-1/{meta.json,event.jsonl,tracking.jsonl,domain.jsonl,manifest.json}
uv run --project python/analytics python -m touchline_analytics.validate_cdf out/m-1
```

## Calibration (method of simulated moments)

The engine is tuned so that simulated matches reproduce real-match statistics measured on the open IDSSE dataset (see `ATTRIBUTION.md`):

```bash
uv run --project python/analytics python -m touchline_analytics.idsse      # download into git-ignored data/raw/idsse
uv run --project python/analytics python -m touchline_analytics.targets    # data/params/targets-idsse.json (aggregates only)
# tune in one-round chunks (~45 min each, 12 matches per evaluation); outputs go to out/ unless --out names a committed file
pnpm calibrate --from data/params/calibration-start.json --matches 12 --rounds 1 --out out/calib-1.json
pnpm calibrate --from out/calib-1.json --matches 12 --rounds 1 --out out/calib-2.json
pnpm calibrate --from out/calib-2.json --matches 12 --rounds 1 --out data/params/touchline-params.json
pnpm realism --matches 16 --out docs/realism/realism-report.md            # held-out matches (default output: out/)
UPDATE_REALISM_BASELINE=1 pnpm --filter @touchline/calibrate test realism-gate  # refresh data/params/realism-baseline.json
```

## Stats models

The stats engine's pass-difficulty (xPass) and expected-goals (xG) models are logistic regressions, and its expected-threat (xT) grid is solved by value iteration over passes and shots, fitted on the seven IDSSE matches, with features taken from event locations and the tracking frame at that moment (all seven tracking files, ~370 MB each):

```bash
uv run --project python/analytics python -m touchline_analytics.idsse --tracking J03WMX J03WN1 J03WOH J03WOY J03WPY J03WQQ J03WR9
uv run --project python/analytics python -m touchline_analytics.stats_models   # data/params/stats-models.json (coefficients only)
uv run --project python/analytics python -m touchline_analytics.xt             # data/params/xt-grid.json (12 x 8 expected-threat grid)
```

`pnpm sim` loads `data/params/touchline-params.json` by default (`--params <file>` to override). Every parameter file must carry provenance with an allowed licence; StatsBomb-derived parameters are refused.

Options for `pnpm sim`: `--seed` (0–4294967295), `--home` / `--away` (club ids in `data/league/league.json`), `--fps` (10, or 25 for video render runs), `--match-id`, `--kickoff` (ISO time), `--out`.

## Stats engine

`packages/stats` turns the domain stream into the metrics of spec §5.2 (pass distance, accuracy and xPass, shot xG and speed, top speed and distance, possession, pressure index, PPDA, field tilt, momentum, control vs chaos, expected threat added, pitch control) and raises signals when thresholds are crossed (goals, big chances, pressure shifts, momentum swings, chaos spikes, speed and distance alerts, difficult passes, milestones, cards, substitution impact). It is incremental and deterministic: every value is kept as of every tick, so a question about minute 60 gets the same answer during the match and afterwards, and a live run and a replay of its files agree exactly.

```bash
pnpm sim --seed 7                      # writes out/m-7
pnpm stats --run out/m-7               # replay it through the stats engine: team metrics, signal counts, top signals
pnpm stats --run out/m-7 --signals out/m-7/signals.jsonl
```

## MCP stats server

Agents read the match only through MCP tools (spec §5.3): `match_info`, `list_metrics`, `get_metric`, `get_series`, `rank_players`, `get_signals`, `get_events`, `get_decision` and `verify_claim`. All are read-only, every answer says which frame it is as of, and nothing later than that is ever returned.

Four more tools look at the match through the engine itself: `pitch_control` (who would win the ball where), `what_if` (re-simulate from a frame with a forced pass, a moved player or a changed team style, against a baseline, over paired seeds), `explain_pass` (every option the passer weighed, on paper by pitch control × expected threat and played out by re-simulation; a better option is reported only when it is clearly better in play) and `suggest_position` (the best spot within 12 m for a player, in attack or defence). The server rebuilds the run from its manifest for these; a run made with parameters it does not have keeps the other tools and says why on stderr.

```bash
pnpm -s mcp-stats --run out/m-7                 # stdio (stdout carries the protocol; logs go to stderr)
pnpm -s mcp-stats --run out/m-7 --minute 60     # the match as it stood at 60'
pnpm -s mcp-stats --run out/m-7 --http 8787     # Streamable HTTP at http://127.0.0.1:8787/mcp
```

An MCP client can launch it directly, for example: `{"command": "npx", "args": ["tsx", "packages/mcp-stats/src/cli.ts", "--run", "out/m-7"]}`.

## Agents

Six Microsoft Agent Framework agents in one workflow graph (`services/agents`, Python 3.12, spec §5.3): the Moment Detector promotes signals to moments, the Tactical Analyst explains them from MCP evidence, the Narrator writes the English draft with every number declared, the Fact-Checker checks every number, name and comparison against the stats server (one retry, then unverified sentences are dropped), the Personalizer writes each viewer segment's cue natively in English, Spanish or Hindi from verified claims only, and the Recap Producer writes half-time and full-time recaps. Every agent has a deterministic fallback. The service speaks A2A v1.0; `packages/agent-gateway` (Effect) sends it a match's signals and keeps the verified cues.

Models: OpenAI `gpt-6.1-sol` for both tiers (set in `services/agents/touchline_agents/config.py`; override with `TOUCHLINE_MODEL_SMALL` / `TOUCHLINE_MODEL_LARGE`). Put the key in the repo's git-ignored `.env.local` as `OPENAI_API_KEY=...`; tests and CI use a deterministic stub and never call a model.

```bash
uv run --project services/agents touchline-agents                     # the agent service on http://127.0.0.1:8100/ (stub model)
TOUCHLINE_LLM=openai TOUCHLINE_TIMEOUT_SCALE=6 uv run --project services/agents touchline-agents   # real models, recorded-run timeouts
pnpm agents --run out/m-7 --segments casual.en.neutral,analyst.es.ironmoor   # cues, traces and recaps cached in out/m-7/agents/
uv run --project services/agents touchline-eval suite --suite ci            # score the agents on six scripted matches (spec §5.3.1)
uv run --project services/agents pytest -m live                             # the few tests that call the real model
```

A real model takes about 5 s per call, so a moment takes about 30 s end to end: real-model runs are recorded runs (the cached cues replay against the match; spec §6). For a live run, give the service a budget below the gateway's (`TOUCHLINE_REQUEST_BUDGET_S=3` with `pnpm agents --budget-ms 4000`): once the budget is spent every remaining agent uses its template, so cues arrive in time; the gateway also keeps any cues that arrived before a request timed out.

Known limits: the checks reject rostered players who were not in the play (in any letter case), but not a name outside the roster altogether, nor a rostered name transliterated into Devanagari; numbers written as words ("two goals") are not checked, so the agents are told never to write them; Hindi must be mostly Devanagari and Spanish must not read as English, but fluency needs a human spot-check; checkpoints are written after every step but a restarted service starts each match afresh.

## Fan app and API

`apps/api` (Effect RPC over WebSocket at `/rpc`) plays matches from a library of run folders. A session plays one match at a speed on the cue bus. Every viewer gets the frames, a scoreboard each second from the stats engine and the agents' cues for their own segment (spec §5.5), in the same match time. Cues come from the run's cue cache (recorded, no model calls), or, with **Live agents** ticked, from the agent service as the match plays. `apps/web` (React, Vite, Tailwind) is the fan app:
- the 2D pitch in the clubs' kit colours;
- the overlays: lower third for casual viewers, side panel for analysts, recap cards;
- a profile switcher and builder (mode, language, club);
- the "Why?" drawer: cause, checked facts, five-minute history, events;
- half-time and full-time recaps;
- a split-screen demo mode, with two profiles on one match.

```bash
uv run --project services/agents touchline-agents &   # the agent service (stub model unless TOUCHLINE_LLM=openai)
pnpm library                                           # simulate the six scenarios and cache their cues for twelve segments (out/library)
pnpm dev                                               # API on :8787 and the fan app on http://localhost:5173
```

`pnpm library --no-agents true` builds a stats-only library without the agent service. The API alone: `pnpm api [--library DIR] [--port 8787]`. Live sessions need the agent service running; with a real model, set `TOUCHLINE_REQUEST_BUDGET_S` on the service below the API's `--budget-ms` (see Agents).

### Studio console, graphics output and ops view

Each session in the fan app links to three more pages, each in its own tab:
- **Studio console** (`#/studio/<session>?seg=…`): every moment the agents explain joins a producer's queue. **Approve** adds it to the presenter's talking points (the analyst text in the producer's language, then the facts its claims were checked against: no model writes them). **Hold** keeps it off air. **Send to graphics** airs it. Every console on the session sees each decision. A raw feed lists every agent cue as it arrives.
- **Graphics output** (`#/graphics/<session>?seg=…&match=…`): a transparent page for a vision mixer or OBS, with the scoreboard and only the cues the producer sent.
- **Ops view** (`#/ops/<session>`): Fact-Checker pass/retry/drop counts, fallbacks, time per agent, requests by outcome, and latency against the spec's budgets: goal to scoreboard under 250 ms, and, live, signal to cue under 4 s (p95). A recorded session reports the request times measured when its cache was made.

## Manager agents

A team's manager agent decides at key moments: half time, the restart after a goal, and the first stoppage after 60' and 75' (a minute moment within 5 minutes of a decision is absorbed by it). The engine pauses the match there and sends the agent a `Situation`: the match from its own team's side up to that tick, and nothing else (no seed, script or future; see `packages/schema/src/manager.ts`). The agent proposes up to three changes (style settings and substitutions). The engine tests each against "no change" on 20 forked futures over the next 10 minutes. The agent then chooses, giving a reason whose numbers must come from those results. Every decision goes to `decisions.jsonl`, so a managed match replays exactly without the model.

```bash
uv run --project services/agents touchline-agents --port 8100     # the agent service (TOUCHLINE_LLM=stub|openai)
pnpm manage --seed 5001 --home ironmoor --away saltmarsh --home-manager agent --away-manager rules   # out/m-5001 with decisions.jsonl
pnpm manage --seed 5001 --home ironmoor --away saltmarsh --replay out/m-5001/decisions.jsonl       # the same match, no model calls
pnpm library --managed ironmoor:saltmarsh:5001,northwick:larkspur:5004   # managed matches in the fan app's library (agent v agent)
pnpm managers:ab --seeds 120 --llm openai                       # A/B: no manager, rule-based, agent (docs/evals/manager-ab.md)
```

`pnpm managers:ab --llm stub` runs the pipeline without a model. With `--llm openai` the A/B run starts the agent service on OpenAI; the key stays in `.env.local` and only the Python service reads it. Cost per match is reported only when `TOUCHLINE_PRICE_USD_PER_MTOK="input,output"` gives the model's price; otherwise the report gives tokens. If the agent cannot propose, the rule-based option stands in. If it cannot choose, or the service cannot be reached, the previous plan stays. Each fallback is counted in the report. In the fan app a managed match shows each decision as a cue, a card with every option's tested gain, and a strip of decisions to reopen them.

## Packages

| Package | What it does |
|---|---|
| `packages/sim-core` | The match engine: one pure, deterministic `step(state)` per 0.1 s tick; pitch control; what-if forks |
| `packages/league` | Fictional league generator: 8 clubs, kits, styles, 160 players |
| `packages/schema` | Effect Schema for the domain stream, signals, metric ids and the agent contracts (exported as JSON Schema for the Python side) |
| `packages/sim` | Effect streams, CDF v0.3.2 writers, run manifest, CLI |
| `packages/stats` | Stats engine: metrics and signals on the domain stream, replay of run folders, `pnpm stats` |
| `packages/advisor` | What-if sessions rebuilt from run folders, better-option explainer, positioning advisor |
| `packages/mcp-stats` | MCP server exposing the stats tools to agents (stdio or Streamable HTTP) |
| `packages/rpc` | The API's RPC contracts (Effect RPC group), shared by the API and the fan app |
| `apps/api` | Match library, playback sessions on the cue bus, live agents, evidence and recaps, studio queue, graphics output and ops report over RPC; `pnpm api`, `pnpm library` |
| `apps/web` | The fan app (React, Vite, Tailwind): pitch, overlays, profiles, "Why?" drawer, recaps, split screen; the studio console, graphics output and ops view |
| `packages/agent-gateway` | A2A client of the agent service: signal batches, recaps, time budget, retry, circuit breaker, cue cache |
| `services/agents` | The six agents, their workflow, the A2A server and the ground-truth evaluation harness (`evals/`) |
| `packages/manager` | Manager agents: key moments, the Situation sent to the model, rule-based and agent managers, option testing by re-simulation, decision log and replay; `pnpm manage`, `pnpm managers:ab` |
| `packages/calibrate` | Match statistics (identical to the Python definitions), tuning knobs, tuner, realism gate |
| `python/analytics` | CDF validation, IDSSE download, real-match targets, realism report, stats-model fitting |

## Status

The engine runs a full match in about 2 s and its output passes the CDF validator in strict mode. Matches include substitutions, fatigue, first-touch errors, ground duels, keeper claims and punches, blocked crosses and shots, deflections behind, and a shot model with separate block, aim and save steps. Scenario scripts (`pnpm sim --scenario late_comeback`) inject tactical causes and record ground truth in the run manifest; `spadl.csv` gives a SPADL view and `--noise on` imitates unsynced real event data. With the calibrated parameters, 16 held-out simulated matches land within 1 SD of real matches on 16 of 19 statistics and within 2 SD on the other 3 (see `docs/realism/realism-report.md`). Passers weigh pitch control and the safety of each kind of pass, and ground passes are struck to arrive at 9 m/s, which brought pass completion to 75 % (real 78 %, within 1 SD) and penalties to 0.5 per match (real 0.4). Known gap: shots on target low (29 % vs 35 %: goal kicks come mostly from wide shots, while about half of real ones follow attacking balls over the byline).

The realism gate (`packages/calibrate/test/realism-gate.test.ts`) runs 16 more held-out matches (seeds 3000–3015). It fails if any statistic moves more than 3.5 standard errors from the committed baseline, or drifts away from the real targets. After an intended engine change, re-run calibration, the realism report and the baseline refresh, and commit all three.

The agents are scored against the scripted ground truth in each run's manifest (`docs/evals/`): with the stub model, six scripted matches give moment recall 94 %, precision 100 %, explanation accuracy 88 %, evidence correctness 94 %, grounding 100 % and persona separation 100 % (`touchline-eval suite --suite ci`). On one scripted match with `gpt-6.1-sol` (23 moments, 100 cues in four segments, 14 minutes, about 200 model calls), every first draft passed the Fact-Checker with all its claims verified, no agent fell back, explanation accuracy was 100 % by the LLM judge (one of three judge runs gave 50 %: the judge varies), decision feedback 83 % and persona separation 100 %; recall was 67 % because the scripted defensive error led to nothing (`docs/evals/agent-eval-live-2026-10-07.md`).
